# Деплой бота на Railway

Бот має працювати цілодобово. На ноуті він живе, поки ти не закрив
кришку — це не той режим, у якому можна кликати людей.

Railway коштує близько $5 на місяць і не залежить від твого мака.

---

## 1. Окремий репозиторій

Бот варто тримати окремо від карти: у нього свій цикл життя,
свої залежності й свої секрети.

```bash
mkdir -p ~/tryvoha-bot && cd ~/tryvoha-bot
cp ~/tryvoha/bot.py ~/tryvoha/gazetteer.csv .
cp ~/Downloads/requirements.txt ~/Downloads/Procfile \
   ~/Downloads/railway.json ~/Downloads/runtime.txt .

cat > .gitignore <<'EOF'
bot.db
*.session
venv/
__pycache__/
runbot.sh
EOF

git init -b main
git add .
git commit -m "Бот повітряної тривоги"
gh repo create tryvoha-bot --private --source=. --push
```

Репозиторій **приватний**: у ньому немає секретів, але й показувати
його поки нема потреби.

Перевір, що `bot.db` не поїхав:

```bash
git ls-files | grep -c bot.db    # має бути 0
```

---

## 2. Створити проєкт на Railway

Відкрий [railway.app](https://railway.app), увійди через GitHub.

**New Project** → **Deploy from GitHub repo** → обери `tryvoha-bot`.

Railway сам побачить `requirements.txt` і `Procfile`, поставить
залежності й запустить `python bot.py`.

---

## 3. Токен

У проєкті: вкладка **Variables** → **New Variable**

```
BOT_TOKEN = твій токен від BotFather
```

Токен вводиться тільки тут. Не в код, не в git, не в переписку.

Після збереження Railway перезапустить сервіс автоматично.

---

## 4. Диск для підписок

Без цього база користувачів зникатиме при кожному деплої.

У проєкті: **Settings** → **Volumes** → **Add Volume**

```
Mount path: /data
Size: 1 GB
```

Бот сам побачить `/data` і покладе `bot.db` туди. Локально шлях
лишається звичайним, нічого міняти не треба.

---

## 5. Перевірка

Вкладка **Deployments** → **View Logs**. Має з'явитись:

```
Довідник: 17078 населених пунктів
Бот запущено | база: /data/bot.db | підписок: 0
Стрім підключено
Ресинк: N загроз, M районів
```

Потім у Telegram: `/start`, назва міста, `/status`.

**Зупини бота на ноуті** — інакше два примірники битимуться за
одні й ті самі оновлення, і повідомлення дублюватимуться.

---

## 6. Перенести підписки з ноута

Якщо не хочеш підписуватись заново — залий локальну базу:

```bash
railway login
railway link           # обери проєкт
railway run bash -c 'cat > /data/bot.db' < ~/tryvoha/bot.db
```

Або просто підпишись у боті ще раз, це швидше.

---

## Оновлення надалі

```bash
cd ~/tryvoha-bot
cp ~/tryvoha/bot.py .          # якщо правив локально
git add . && git commit -m "опис змін" && git push
```

Railway підхопить push і передеплоїть сам.

---

## Що моніторити

**Логи.** Обриви стріму — норма, вони мають виглядати так:

```
Стрім обірвано (ConnectionClosedError), пауза 1 с
Стрім підключено
Ресинк: N загроз, M районів
```

Якщо після обриву не з'явилось «Стрім підключено» — бот завис,
і це найгірший сценарій: він живий, але мовчить.

**Ліміт годин.** Безкоштовний тариф Railway дає обмежений час на
місяць, цілодобовий бот його вичерпає. Потрібен платний план,
близько $5.

**Пам'ять.** Довідник тримається в пам'яті, це десятки мегабайт.
Якщо побачиш OOM — скажи, винесу довідник у SQLite.
